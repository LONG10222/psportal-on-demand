# 手机端需求与后台可行性

更新：2026-10-19，依据用户最新要求。

## 已确定的产品方向

手机端只提供订阅链接导入，由本应用自己的内置核心完成连接与局域网 HTTP/CONNECT 共享。不增加关联另一款 Clash／代理应用的入口，不要求同时打开第二款代理应用。Mac 的关联模式不影响手机端范围。

保留订阅用量与到期信息、手动节点选择、最低延迟自动策略、设备与连接统计、中英文热切换，以及其他设备的 Wi-Fi 手动代理指引。默认优先端口 10081；实际地址以系统分配与界面显示为准。

## 后台持续共享是尚未解决的核心要求

用户要求手机 App 切换后台后仍可持续为其他设备提供代理。当前实现**不满足**：

- `ProxyModel.scenePhaseChanged`、UIKit 后台通知及设备锁定通知会停止监听。
- 现有背景任务仅用于完成停止与连接清理，不用于继续接收设备请求。
- 已通过的模拟器测试验证的是“后台停止”，不能作为“后台常驻”的证据。

移除 Stop 回调并不能解决系统挂起。不能将保持亮屏、调试器附加状态、几秒钟后台存活或一次模拟器连接解释为后台能力已完成。

## 苹果公开 API 核实

1. [UIKit 后台时间扩展](https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time)：用于完成有限工作，系统会挂起普通后台应用，必须处理执行时间耗尽。
2. [Continuous Background Task](https://developer.apple.com/documentation/backgroundtasks/performing-long-running-tasks-on-ios-and-ipados)：用于用户发起、可完成且有真实进度的工作；可能无法立即执行，也可能被取消或到期。文档不能证明无限期代理服务受支持。
3. [TN3120](https://developer.apple.com/documentation/technotes/tn3120-expected-use-cases-for-network-extension-packet-tunnel-providers)：Packet Tunnel 的推荐用途是设备 VPN；明确将托管网络监听器或代理服务器列为不支持的用途。不能仅把本应用的 LAN 监听器搬入扩展就宣称后台可用。

手机本机的 VPN 流量处理，与替局域网／个人热点设备提供代理入口，是两个不同的网络路径。不能以另一个 VPN 客户端的后台状态替代对本产品的验证，也不能为了后台运行悄悄移除局域网共享这一核心功能。

## 后续工程门槛

- 先找到适用于“接收局域网客户端连接”的受支持执行模型，再实施架构变更；目前没有已确认可满足本要求的 iOS 方案。
- 如采用扩展，需要单独核实 entitlement、签名、部署和热点入站可达性；新增 VPN 能力不等于局域网共享已经可行。
- 在真实 iPhone 上、脱离调试器，测试切后台、锁屏、长时间空闲、持续流量、重新接入、Wi-Fi／蜂窝热点切换、低电量和系统回收。每项记录实际持续时间、连接结果和终止原因，不能只凭模拟器通过发布后台支持声明。
- 架构问题解决前保留明确的前台限制，不增加虚假的“后台常驻”开关。当前产物仍是前台开发预览，不能视为满足完整手机需求。
