# 星渡主程序：游戏与加速器集成预览

## 0.6.0：共用核心、服务端用量与实时流量

导入链接后，游戏共享的设备入口和内置 Clash 的本机入口使用同一份已接受的订阅、节点选择与一个核心进程。工作台显示两个实际地址，运行中可以在“游戏共享”和“独立订阅”之间查看，保持当前会话。游戏共享也可明确选择“跟随 Clash”：此时转发到已经运行的电脑 Clash，使用其当前订阅，不另导入一份，也不改写其配置。切换来源需先停止。

独立订阅和 Clash 联动展示已用、总量、剩余、到期日及更新时间。独立来源使用已接受链接；Clash 来源只读已知客户端当前活动配置的链接与已有用量。服务端 `subscription-userinfo` 每 60 秒核对一次，支持手动刷新（最短 5 秒）。缺少链接时标明本地快照，缺少头或更新失败时保留上次数据和时间，不假装零用量或更新成功。订阅链接与账号不进入发行包。

实时速度约每秒刷新，累计值来自星渡自己实际转发的字节，按已验证目标地址区分“局域网”和“外网”。共用双入口汇总统计；借用 Clash 时只统计经过星渡入口的流量，不声称覆盖 Clash 其他应用、电脑网卡或整个家庭。网络协议、TLS 与运营商计费口径可能不同，通道累计不会写入或替代套餐额度。

工作台导入后折叠输入框，保留“更换订阅”，启动/停止按钮与两块数据卡集中显示。鲜牛游戏库、官方目录更新、免费项目计时处理与既有高级页面保留。接入范围仍明确选择仅本机、局域网或已开启的热点，不自动修改 Windows 热点、ICS、系统代理、DNS、VPN 或路由器。

安卓提供独立 App，内置 Mihomo，使用自己的一个会话与导入链接，展示服务端用量、实时速度和局域网/外网累计。它不会读取其他安卓 Clash 应用的私有配置。带 GEOIP 规则的内联订阅可明确选择“全局”；规则模式仍要求受支持的规则格式。手机本机应用接管需要用户确认 Android VPN 授权。预览 APK 使用测试签名，发布时附带对应 GPL 源码及依赖许可。

0.6.0 在专用 Android 15 模拟器虚拟 Wi-Fi/NAT 下验证 Windows 双入口：直连外网与电脑其他 Clash 入口被阻断，星渡入口的 Steam HTTPS 返回 200，局域网只读请求返回 200，切换页面保持同一后台与核心，停止后无法回退直连。实体热点、任意游戏 UDP、PS5 NAT 和新鲜牛登录不属于这组验收。安卓 App 的独立验收结果见随包 evidence 文件。

## 0.5.1：工作台模式与启动流程修复

Windows 默认统一打开工作台，包括上次保存为鲜牛模式的配置；显式 `--page overview` 与 `--page games` 仍分别打开指定页面。返回工作台时同步实际模式，鲜牛只显示游戏库入口，不显示订阅和通用共享控件。仅本机隐藏设备白名单与热点说明，并显示本机应用所需的地址；Clash 联动后的设备与本机共享在高级模式中也可选择，提示不再声称仅支持设备专用模式。工作台支持小窗口滚动。

接入方式在成功保存启动配置时记录。仅本机配置保持本机范围，已选热点关闭时不会回退到普通局域网；解除 Clash 联动恢复独立订阅及原接入范围。没有独立订阅时，游戏共享不再自动改为复用电脑 Clash。

每次启动前重新只读检测接入网络，检测中同一按钮可取消；导航离开后，迟到的结果不能启动后台。缺少核心时，准备完成后重新检查网络再启动，取消或离开工作台会撤销该次自动启动意图。原导入、节点、规则与后台停止流程保留，不开启系统热点或改写电脑网络设置。

本轮重点验证模式、来源恢复、异步取消、目标持久化与冻结窗口，0.5.0 的 Android HTTP/HTTPS 传输验收记录继续保留。0.5.1 没有重新开启鲜牛会话，也不把界面回归测试表述为实体热点、游戏 UDP 或新增免费计时实网验证。

## 0.5.0：Windows 统一工作台

默认打开工作台，提供游戏共享、鲜牛加速、Clash 联动和独立订阅四个入口。鲜牛入口直接进入已有游戏库；其他用途不显示鲜牛游戏。原有概览、节点、设备、规则和高级参数仍可使用。工作台复用既有导入、启动、回滚与停止流程，不另写一套订阅解析器。

Clash 联动检测当前用户已启用的本机 HTTP 系统代理，建立星渡自己的局域网入口。源订阅暂存并在解除联动时恢复，停止共享不停止或改写已有 Clash。该共享入口支持模拟器 NAT 到宿主机的来源地址；原游戏模式仍排除宿主机，访问名单不被静默扩大。高级配置中的旧“Clash 模式”继续表示独立核心仅供本机使用，与工作台“Clash 联动”有不同含义。

独立订阅使用星渡自有的核心进程与运行目录，保留完整配置的节点、分组和规则，关闭配置中的透明接管及系统监听。可选择仅本机、当前局域网或已确认的 Windows 热点；游戏共享使用相同订阅供设备接入。导入本身不启动监听，工作台切换不覆盖其他来源。

热点检测只读 Windows 热点运行状态、实际 Wi-Fi Direct 适配器与 IPv4 子网；不会猜测固定地址。热点未开启或地址不明确时拒绝启动。手动设备名单与新网络不匹配时要求先更新名单或明确勾选允许所选网络。打开热点设置只打开 Windows 设置页，不自动启用热点、ICS、DNS 或系统代理。热点自身会共享电脑原网络，需在设备上填写代理才能使用星渡的 HTTP/HTTPS 通道；任意游戏 UDP 不在该通道范围内。

2026-10-26 使用冻结版 Windows 后端及专用 MuMu Android 15 实例实测。客体 IPv4/IPv6 OUTPUT 只允许测试入口、loopback 和已建立的 ADB 回复；外网 TCP、直连 DNS及宿主机其他 Clash 入口的探测均失败。Clash 联动及独立订阅分别访问 Steam 商店和公开 Web API，两项 HTTPS 均为 200、默认 TLS 校验且使用系统 HTTP 代理；独立核心从停止状态按需启动。两条路径停止后请求均失败，没有直连回退。首次冷启动探测遇到客户端超时，扩展测试客户端等待时间后复测通过；未通过宿主机预热伪造冷启动结果。

本次订阅包含 52 个节点，验证了解析与上述链路，没有逐个验收全部线路。模拟器使用虚拟 Wi-Fi/NAT，并非实体手机连接 Windows 物理热点；本机热点关闭，因此实体热点、游戏 UDP、PS5 NAT 与鲜牛新登录后的免费实网启动仍未验收。测试结束已关闭模拟器和本次自有核心/监听、恢复代理与 root 开关并移除测试 APK，原 Clash 保持运行。测试订阅与账号均不进入源码和发行包。

## 0.4.2：尊重官方免费项目的计时规则

此前目录解析丢弃了官方 `is_free`，Windows provider 对所有 managed 游戏都执行恢复计时。本机官方公开 XML 中“STEAM：社区/商店”（12）明确为 `is_free=1`；Steam 客户端下载（808）、Steam 远程同乐（2871）则为 `0`。现保留免费标记，游戏卡片显示“免费”，并按每个官方项目判断，不以标题包含 Steam、会员试用余额或自定义配置开关推断免费。

启动前从当前官方客户端目录解析计费规则；缺少客户端时可使用带明确标记的官方缓存/随包快照。免费项目仍须官方 start/token 验证，但不调用 `/client/member/recovery`，停止时只结束本页会话，不调用 `/client/member/suspend`，不拥有或改写全账号计时。官方拒绝免费启动时直接失败，不退回恢复计时重试；规则缺失或当前官方目录损坏时不启动、不恢复计时。已确认付费项目保留原流程。

目录的自动更新同时更新免费标记；官方规则变化后，下次启动重新读取。随包公开快照已补回原始 XML 标记，来源 SHA-256 为 `34aeafbde45533c3b2d8922a52d2e1eb9ced25c3236216c218721612ab0e0817`，3018 项中 155 项标记免费。确认窗口、运行状态和停止结果也区分免费项目，避免误提示“恢复时长”或“已暂停全账号”。

受控测试覆盖免费启动/停止全程无 recovery/suspend、拒绝免费启动不转付费、未知规则拒绝启动、付费路径保持恢复计时及免费标记解析/更新。当前保存的官方登录读取返回 400011，故本轮未进行新的实网启动测试，也未变更计时；需用户自行重新授权后再验收。此前先恢复时长完成的 Steam HTTPS 测试不能证明免费计时路径正确。

## 0.4.1：模式隔离与官方数据更新

修正 0.4.0 中“按钮只跳转、游戏入口常驻”的行为。选择“加速器模式”现在实际进入该模式，并使用已有可恢复的配置备份；只有该模式显示游戏导航。切换到游戏、混合或 Clash 模式后回到概览，恢复原订阅与设置，并隐藏游戏导航；即使直接要求显示 Games，也会返回概览。游戏页顶部可以直接切换模式。存在本页加速会话时要求先停止，避免跨模式遗留运行。启动器不再无条件传入 `--page games`。侧栏显示 `v0.4.1`，用于确认实际运行构建。

游戏目录启动时读取已安装鲜牛官方客户端的公开 `gamedata/gamelist.xml`，游戏页处于活动且未加速时，每 60 秒检查来源文件是否变化，变化后自动同步新游戏、区服与图标信息。保持搜索、收藏和仍有效的选择；文件不变不重复写缓存。客户端写入中、文件损坏或来源缺失时保留上一次有效目录并显示缓存状态。它跟随已安装客户端的目录更新，不把缓存标为鲜牛云端最新，也不会代替官方更新器下载/执行新程序。

线路由 `/client/accelerate/linelist` 动态读取：选游戏/区服时查询；空闲时每 60 秒刷新当前所选方案；一键启动前若线路超过 60 秒则先重新获取。设置中的“同步游戏与线路”可立即检查。加速运行时不更换正在使用的游戏、区服或线路；停止后继续同步。线路查询不调用 start/recovery 或恢复计时。

本机实测公开目录 3018 项，连续两次 Steam 线路读取均实际请求官方接口；另有受控测试验证官方文件新增游戏/区服会进入界面、线路响应变化可替换旧列表、损坏更新不覆盖有效缓存。此次没有启动付费加速或重新进行网络流量验收。

## 0.4.0：简洁的一键入口

概览中的“加速器模式”按钮直接打开同窗口游戏库，与左侧“游戏”入口一致。这个导航动作不切换底层代理模式，也不改写原订阅、LAN 地址、节点或配置文件；旧的标准 HTTP/SOCKS5 联动入口仍保留在高级路径中。已保存为旧 accelerator 模式的启动配置默认进入游戏页。

主界面保留账号、分类/搜索、游戏卡片、已选游戏以及一个“一键加速”按钮。区服/线路默认收起，可展开修改；设备、账号刷新、目录同步及网络参数放入“设置”。UU/雷神客户端入口移到“更多”，本轮优先鲜牛。

首次需自行微信授权，并确认同账号其他会话已停止。以后选游戏、点击“一键加速”即可沿用保存的区服，自动加载官方可用线路；等待中可以取消，取消或换游戏后的迟到结果不会启动加速。线路尚未读取完成时不要求用户再次点击；没有可用线路或读取失败时会停止准备，不启动付费会话。自动选择不代表测得了最低延迟。

运行后同一个按钮变为“停止加速”。自有 managed 会话会停止并申请暂停计时；复用会话只停止本页共享。关闭简洁页面同样仅清理本页会话。暂停失败保留错误提示，不把未确认状态写成已暂停，也不会卡在反复退出中。选择 Steam 商店/社区时，本次通道关闭商店直连例外，其他模式配置保留。

“一键”指准备和开启鲜牛显式代理通道；应用/设备仍需接入该代理，不代表已安装透明网络驱动或自动接管所有 PC/主机游戏 UDP。主界面保留简短代理/UDP 状态，详细说明放入设置。此次仅做 UI 与受控行为回归、冻结程序真实入口检查，没有重新开始付费会话或扩大先前的网络验收结论。

在星渡左侧点击“游戏”，直接进入同一个窗口中的加速器工作区。它是原 `PSPortalProxy` 主程序的一部分，不通过启动独立鲜牛 EXE 来伪装集成。原有概览、订阅、节点策略、规则、局域网共享、日志、游戏/混合/Clash 模式及配置格式保留。

## 两种接入

| 加速器 | 内置 provider | 已安装客户端联动 | 本轮验证边界 |
|---|---|---|---|
| 鲜牛 | 官方登录、时长、完整目录、区服/线路与已有原生 TCP/UDP | 读取公开安装信息与客户端游戏 XML | 目录和显式代理传输已有记录；字面 IP TCP、完整主机 UDP/NAT 仍有限制 |
| 网易 UU | 尚未取得可验证的公开嵌入引擎/账号接口 | 识别卸载项、归属明确的进程和 EXE；可打开官方客户端 | 本机未安装，检测规则仅做受控测试；未声称已读取 UU 游戏库或转发游戏 |
| 雷神 | 尚未取得可验证的公开嵌入引擎/账号接口 | 识别卸载项、归属明确的进程和 EXE；可打开官方客户端 | 本机未安装，检测规则仅做受控测试；未声称已读取雷神游戏库或转发游戏 |

这套注册表明确区分安装、运行、公开目录读取、账号、传输及实际流量接管。增加品牌描述不等于完成其内核适配。切换到 UU 或雷神不会把鲜牛的游戏库、余额或会话当作该品牌的数据。未来接入器应先补充真实来源和协议验证，再打开对应能力。

用户选择“标准代理入口”时，进入原有独立加速器模式，按真实 HTTP/SOCKS5 握手与 TLS 验证。该旧模式仍限制为 Steam 网页 TCP，不能推广成任意品牌的全游戏 UDP 接管。没有从进程运行或开放端口推断游戏已经加速。

## 鲜牛页面

保留 3018 项公开官方目录、图标、分页、分类、收藏、最近选择以及每游戏区服/线路方案。页面以惰性方式创建；仅浏览和读取线路不 start/stop，也不恢复会员计时。账号沿用当前用户 DPAPI 私有存储，与正常星渡订阅分开。

独立鲜牛预览和主程序共用这份账号存储的实例锁。先关闭独立预览，再在主程序中使用；不会同时启动两份相同账号的管理界面。切换品牌前要求停止本页正在运行的加速。关闭主窗口会等待本页自己的监听和会话停止；不会接管或停止其他入口的会话。

## 保护既有功能

- “游戏”是新增导航页。打开和离开它不改变原 product_mode、订阅、来源、节点偏好或配置字节。
- 页面只使用 `SPGame.*` 样式，不切换主窗口主题、不重写主窗口标题或退出处理。快捷键只在该页面激活。
- 主窗口原启动/停止栏仅在游戏页隐藏，离开后恢复，避免误把原模式的按钮当作游戏 provider 的按钮。原运行实例的生命周期保持独立。
- 新入站助手是可选、需用户确认提权的步骤，限定主程序、私有 LAN 地址与选定设备；不会自动修改 DHCP、路由、网关、DNS、ARP 或 Windows 系统代理。

运行源码：安装 `portable/requirements-build.txt`，在 `portable` 执行 `python -m portalproxy.desktop --page games`。完整构建仍走 `portable/build.py`，包含原主程序、鲜牛模块、公开目录和所需许可。预览启动器使用 `%LOCALAPPDATA%\StarPassGamesPreview\config.json`；日常配置不被预览覆盖。

## 0.3.1：微信二维码与安卓隔离复测

官方二维码当前返回 JPEG。已改用 Pillow 解码 JPEG/PNG，再显示到 Tk，避免原生 Tk 图片加载失败；获取/轮询失败会在登录窗口中提示并提供重新获取。图片或控件回调异常不再中断页面事件泵，避免登录失败后无法正常退出。真正的扫码、微信授权和额外验证仍由用户完成。

2026-10-25 使用本机专用 MuMu `StarPassValidation` 实例及无账号的 Android instrumentation 测试应用复测源码 provider。宿主机防火墙不足以阻断模拟器通过 NAT 到电脑其他 loopback 代理，最初的负向探测因此拒绝验收。补充客体 IPv4/IPv6 OUTPUT 限制后，只保留 `10.0.2.2:18082` HTTP 测试入口、客体 loopback 与已建立的 ADB 回复；外网 IPv4/IPv6 TCP、直连 DNS、电脑 Clash 入口均被实际探测拒绝。

选择鲜牛 Steam 商店/社区（游戏 12、区服 154、线路 120），并在测试配置中明确关闭 `steam_store_direct`。安卓应用通过系统 HTTP 代理访问 Steam 商店和公开 Web API，两项 HTTPS 均返回 200、使用默认信任链和主机名校验；provider 记录 2 条原生 TCP、0 条错误，没有直连计数。停止 provider 后，两项请求均失败，负向隔离测试在加速前和加速中均通过。

该结果验证安卓 Wi-Fi/NAT 下的 Steam HTTPS 代理链路与断路行为，不是 Steam 原生客户端、实际游戏 UDP、PS5 NAT、Wi-Fi 手机现场或新冻结程序传输的验收。测试后官方 stop 与暂停均确认，监听关闭，模拟器退出，临时 APK 卸载，5 个代理键恢复，测试实例 root 开关恢复关闭，专用宿主防火墙规则移除。
