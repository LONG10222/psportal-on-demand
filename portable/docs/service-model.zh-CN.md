# Windows 0.7.0：服务与地址

游戏共享是设备入口。鲜牛、Clash 联动、独立订阅是外网来源，分别控制；切换页面不停止服务、不替换订阅。

| 项目 | 启动内容 | 地址 | 单独停止时 |
| --- | --- | --- | --- |
| 游戏共享 | 所选局域网/热点上的 HTTP/CONNECT 入口 | 所选网卡 IP:10081；占用时显示实际端口 | 只关闭设备入口 |
| 独立订阅 | 自有本机入口，外网请求按需唤醒自有核心 | 127.0.0.1:10080；占用时显示实际端口 | 只停止自有入口与核心 |
| Clash 联动 | 使用已检测到的外部 Clash HTTP 代理 | Clash 的实际本机端口 | 解除联动，保留原 Clash 进程 |
| 鲜牛加速 | 已集成的游戏库与鲜牛通道 | 鲜牛通道实际本机端口 | 沿用鲜牛会话停止和计时处理 |

所有星渡服务默认关闭。已有 Clash 保持原有状态。可以同时开启游戏共享和三个来源；共享入口的外网一次只走所选来源，不会把三个来源串接。选择“仅局域网”时不提供外网。

设备始终填写游戏共享页面显示的地址。独立订阅的核心和配置只有一份，游戏共享通过它的本机入口转发，不重复导入订阅或再启动一份核心。启用来源不会自动放宽设备名单。热点使用 Windows 已建立的网络，不自动改动 ICS、系统代理、VPN 或防火墙。

所选来源停止/失效后，已有局域网流和共享监听保留，外网流终止，新外网连接失败；不会改走其他来源或电脑直连。切换来源也仅终止原外网流。关闭应用会清理本实例的共享、自有核心和鲜牛会话，不关闭其他应用的 Clash。

## 订阅与流量

独立订阅和 Clash 当前订阅分别读取服务端用量、总量和到期时间；每 60 秒核对，可手动刷新。切换页面不会清空上次数据，刷新失败保留上次完整值和更新时间。服务端不返回用量时明确显示缺失，未导入时明确显示“未导入订阅”。用量查询优先 HEAD，必要时仅 GET 响应头，不重复下载配置。

游戏共享的即时速率和本次累计按局域网、外网分别显示。独立订阅显示自身通道流量。它们可能经过同一条请求，不能相加作为订阅计费量；订阅计费仍以服务端用量为准。Clash 用量来自当前配置与服务端，不把整个电脑网卡流量当作该订阅的流量。

## 验证边界

Windows 回归测试覆盖独立生命周期、三来源切换、来源断开后保留局域网、订阅缓存隔离、部分数据与刷新失败。实际 N1 局域网客户端已验证 HTTP 与 Steam HTTPS，以及停止来源后局域网继续、外网失败。

安卓模拟器组件实测通过共享入口接入 Clash，Steam 商店和 API 均返回 HTTPS 200，使用系统信任链校验证书。虚拟 WiFi 使用临时的本机别名转发到同一个游戏共享入口；不是直连 Clash。IPv4/IPv6 直连、直连 DNS 和宿主机其他代理均被拦截，关闭来源后外网失败。临时别名、隔离规则、代理设置和测试探针在测试后清理，模拟器关闭并关闭 root。

全规则独立订阅在首次启动时可能需要 Mihomo 下载 GeoSite/MMDB。第一次冻结界面实测 Steam 200；后续空缓存组件复测遇到 GitHub 规则库下载超时，不能视为独立订阅在空缓存、不可达下载源环境下也通过。界面会显示核心失败，游戏共享不会改走直连。未改写订阅规则来绕过缺失数据。

鲜牛现有登录校验返回 400011；本次未登录新账号、未启动新计费会话，鲜牛在线多来源共存未实测，使用本地替身验证其生命周期。HTTP/CONNECT 测试不代表游戏 UDP、主机 NAT、语音或 Android VPN 全量接管通过。安卓模拟器的虚拟 WiFi 不等同于实体手机连接 Windows 热点；安卓 0.6.0 与软路由本次不改动。
