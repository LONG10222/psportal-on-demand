# 固定入口与三模式验证 — 2026-10-26

## 实机与范围

N1 ARM64，iStoreOS 22.03.6 / fw3。配套 `luci-app-starpass 0.3.5`、`xianniu-router 0.5.1`。前代程序与私有备份保留。以下为 HTTP/HTTPS 接入与服务状态验证，不作为 PS5 游戏 UDP、NAT、帧率或整机重启验收。

## 实际结果

- 加速器关闭时，原固定入口访问普通 HTTPS 网页返回 200；局域网 HTTP 200。
- 最终版本模拟旧公共游戏监听器并执行自动迁移，原端口和启用状态保留，后端转为回环。安装升级自动恢复已配置的入口，不恢复付费会话。
- 官方鲜牛港服会话开启后，同一入口经本机 native SOCKS 后端访问 PlayStation 返回 HTTPS 302。
- 从加速器切到星渡，官方会话停止，官方计时确认暂停。同一加速器入口再次直连 HTTPS 200，没有修改设备代理地址或端口。
- 星渡使用游戏的原公共入口。开启后关闭游戏后端，复用 OpenClash 核心，外部连通性检查 HTTPS 204；关闭后同一入口普通 HTTPS 200。
- 星渡开启期间，加速器关闭入口仍独立直连，未被串入 OpenClash。
- 重新开启游戏会停止星渡关联的 OpenClash 核心。仅测试主机可访问的临时探针通过生产转发类进入原按需游戏后端，返回 HTTPS 204；探针与临时端口随后移除。
- OpenClash 启用状态双向同步；手动代理实例丢失后自动恢复，保存的星渡状态保留。开启期间仅更改相关启用开关和原开机入口，避免原全网启动脚本在重启时接管网络；停止后恢复原开机设置。
- LuCI 三个入口、星渡启停、同一端口展示与嵌入的原 OpenClash 管理页经过页面检查。原页正确识别运行中的核心。
- 原网络、DHCP、防火墙配置摘要不变。规范化后的 iptables、IPv4 policy rules 与主路由表一致。OpenClash 其他配置选项与原值一致；启用标记随开关改变，原 YAML 不覆写。

## 测试

14 个 Lua 测试入口、20 项安装／打包测试、2 项启动脚本测试、70 项鲜牛测试及 13 项新入口测试通过。新测试覆盖：

- 真实本地 TCP 的直连、HTTP CONNECT、SOCKS 接入与关闭／开启／关闭保持同一个监听端口。
- 后端认证只发送到固定本机代理，客户端认证不传给外部站点。
- 并发客户端路由选择互相隔离；非游戏设备不会借用游戏订阅。
- 星渡启动失败恢复游戏状态，开启顺序保证互斥。
- 切换前停止与暂停顺序、暂停失败不完成页面切换。
- OpenClash 原 YAML 保留，包括多行值；手动实例关闭 TUN、redir、tproxy 与 fake-IP。
- 原启用状态的恢复与 OpenClash 关闭后的联动清理。

## 修复中发现的问题

目标系统的系统 DNS 不能解析普通网页；入口使用现有 LAN DNS，未改系统 DNS 配置。其精简 Ruby 没有 JSON 库，准备器使用自带 Psych 的 YAML 输出，避免增加该依赖。最初的配置检查／早发探针未通过，均在对应修复或就绪等待后重新验证；未用旧结果替代最终行为。

## 限制

入口是常驻轻量服务。功能关闭时直连，不代表物理关闭软路由后代理仍可用。已有 TCP 连接在出口切换时关闭并由应用重连。直接连接恢复的是普通宽带可达范围，不能保证直接访问受限站点。

对代理设置不生效的应用和任意游戏 UDP，固定 HTTP 入口不会自动接管。尚未进行整机掉电重启、长时间游戏或本次最终版本的大体积下载验收；前一版本未压缩 Steam 大响应中断的问题仍未作为修复结论。
