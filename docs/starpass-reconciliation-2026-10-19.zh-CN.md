# StarPass 最新上传校验与修复

本次以用户最新提交 `05bf04ed86669ae51dffe639de657e6a11a16e7f` 为基线，
保留 iOS 四页界面、显式限时后台实验、项目标识和全部现有许可。

## 已定位并修复

- Windows portable 构建：新增品牌测试用系统默认编码读取 UTF-8 源码，
  在非 UTF-8 系统上误报名称不一致。现在显式指定 UTF-8，并模拟 CP1252 回归。
- macOS unified 打包：新图标数据目录让 PyInstaller 增加一个应用内链接，
  原严格清单未包含它。仅接受 `Contents/Frameworks/assets → ../Resources/assets`，
  同时将全部品牌文件和 Dock 图标绑定到保留资源清单的哈希；错误目标、额外／缺失链接、
  错误／额外／缺失图标仍拒绝。代码签名、二进制来源和解包验收门禁保持有效。
- 源码品牌检查：旧测试要求 iOS 完全没有后台声明，与最新的有限实验冲突。
  更新为精确验证 `processing` 和单一应用任务标识，并保留默认关闭、明确授权、
  过期停止以及不提供整机 VPN／完整规则的边界。

- iOS 设置和说明页：去除与新实验相冲突的“完全不支持后台”旧文案，保留默认前台、
  系统明确授权、有限时长和真机未验证的说明；不更改布局或生命周期。

- 后续 CI 暴露依赖收集器只保留 stderr、丢失 `go mod download -json` 的 stdout 错误。
  现保留有界诊断，只有合法 JSON Error 中明确的瞬态错误允许沿用最多三次重试；
  完整输出中的校验、权限及证书错误优先立即失败，非法 JSON 不作为重试依据。
- 两次独立 iOS 运行分别遇到不同的两秒元数据回调等待超时，未触发功能断言。
  测试使用独立高优先级串行队列和十秒正向等待预算，门闩必须显式释放且超时即失败；
  原有否定等待及会话顺序断言保留，生产队列优先级和生命周期完全不变。

## 最新 iOS 的实际范围

默认仍为前台共享。用户主动开启的 iOS 26+ 真机实验只在系统实际授予持续处理任务后，
允许限定 15／30／60 分钟的后台及锁屏共享；系统可提前结束。任务不排队、续期或自动重启，
旧 SDK 和模拟器明确不可用。模拟驱动和模拟器通过不等于真机系统已授权，
真实热点、锁屏联网、游戏机、长期运行与签名安装仍待验证。

## 图标状态

人物轮廓版已选定。此次构建修复先保留仓库现有整套图标与资源清单一致，
完整人物轮廓图标包另行提交；不能把部分尺寸替换当成跨平台图标已经完成。

## 验证方法

以本修复提交的 GitHub Actions 终态为准。此前最新 iOS 工作流的 38 项测试中
37 项通过、1 项硬件检查跳过；后续独立运行显示两秒测试调度敏感，
采用上述测试夹具修复并重新验证，不据此改动生命周期逻辑。所有发布产物仍为开发验证用途，不提供生产签名或永久后台保证。
