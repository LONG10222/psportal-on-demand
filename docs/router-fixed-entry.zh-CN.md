# 三种模式与固定代理入口

游戏、加速器和星渡使用同一个管理页。先完成一次接入设置，以后只操作开关；设备不用换 Wi-Fi、改 IP 或反复删除代理。

## 安装与首次配置

从本分支 Actions 下载配套 IPK 与校验文件，在路由器中一次安装 `xianniu-router_0.5.1_all.ipk` 和 `luci-app-starpass.ipk`。已有版本的配置会保留并备份。源码方式还需预先安装共享模块与 Python；具体依赖见各模块说明。

首次打开在高级设置中确认软路由地址、局域网 DNS、游戏设备及订阅来源并保存。之后复制页面显示的入口到设备，日常不再改这些字段。已有游戏配置升级后沿用原端口。

## 设备怎么填

| 用途 | 填写的代理 |
| --- | --- |
| Portal 游戏模式 | 首页显示的游戏／星渡公共入口 |
| 星渡访问国际网络 | 同一个公共入口，地址、端口与游戏模式一致 |
| 鲜牛加速器 | 加速器工作区显示的入口 |

例如公共入口可以是 `192.168.50.2:10081`，加速器入口可以是 `192.168.50.2:10082`。这些是示例；复制自己页面显示的地址。IP、网关和 Wi-Fi 保持现有设置。

游戏与星渡共用端口，所以同时只开启其中一种。加速器可以独立运行。公共入口由一个常驻的小进程监听，不让两个服务争抢同一个端口。

## 关闭之后会怎样

关闭加速器或星渡，关闭的是对应的代理核心／会话。入口仍然接收设备请求，改为从软路由默认出口直连，使用已配置的局域网 DNS。普通网页仍可访问；国际网络恢复为当前宽带直接连接时的可达范围。

公共入口跟随当前已启用的游戏或星渡；两者均关闭时直连。关闭正在运行的星渡不会自动启动游戏。加速器入口始终独立。

设备的网关没有被修改。“默认出口”指软路由转发该请求时使用自己的默认路由。HTTP/HTTPS 代理只处理遵守这项设置的请求，不接管任意游戏 UDP。

已经建立的 TCP 连接不能迁移出口；切换后会关闭旧连接，应用重连后使用新出口。设备不用重新填写代理。

## 游戏模式

点击开启后，公共入口为已配置的游戏设备转交请求，外网流量按需启动独立 Mihomo，60 秒无外网收发后休眠。局域网访问不唤醒核心。

开启游戏模式会先关闭星渡及它关联的 OpenClash 核心。关闭游戏模式后入口直连。其他局域网设备即使填写这个入口，在游戏模式下也走直连，不借用游戏设备的订阅。

## 加速器模式

设备、备注、游戏、区服和线路沿用鲜牛工作区。开启后，固定入口转交本机鲜牛 SOCKS 通道；停止后暂停官方付费计时，并恢复直连。免费项目仍按官方标记处理，不操作全账号计时。

从加速器页面切到星渡页面，先停止当前会话并确认官方计时已暂停。未确认时不完成切换。再次使用鲜牛需要明确启动，不会因返回页面或重启路由器恢复付费会话。

## 星渡模式

点击开启会先关闭游戏模式，再复用 OpenClash 的配置和核心。页面内展开 OpenClash 管理即可使用其现有界面；不复制节点或订阅管理页。

如果 OpenClash 已在运行，直接使用它的代理入口；否则启动其核心的仅手动代理实例：关闭 TUN、redir、tproxy，使用真实地址 DNS，不运行 OpenClash 的全网 DNS／透明转发启动脚本。原 YAML 配置文件保留不动；OpenClash 的启用开关随模式同步。仅手动代理期间暂时停用它的原开机脚本，由星渡恢复手动实例，防止重启时意外开启全网接管；关闭后还原原开机状态。

OpenClash 服务状态与星渡状态联动：已有 OpenClash 开启会转入星渡出口并关闭游戏后端；它停止后，星渡入口恢复直连。通过 OpenClash 自己的完整启动功能开启时，仍按该插件原配置执行网络规则。

## 开机与维护

固定入口开机启动，保留已经启用的游戏或星渡模式，两者不会同时启用。鲜牛付费会话不自动启动。页面选择单独保存。

接口通过当前 LAN 子网限制来源，只处理主动填写代理的设备。网络、DHCP、防火墙和 Wi-Fi 不由常驻入口修改。MAC 备注及游戏方案继续保存在本机。

配套版本：`luci-app-starpass 0.3.5` 与 `xianniu-router 0.5.1`。源码安装器还需要 Python 和鲜牛模块提供的共享 HTTP 库；IPK 会声明模块依赖。既有配置在首次开启相关功能时自动私有备份并启用 `gateway_enabled=1`，游戏后端迁移为只监听回环，公共入口保留原地址和端口。
