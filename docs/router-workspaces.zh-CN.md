# 游戏模式与加速器模式

星渡在 OpenWrt / iStoreOS 中提供两个工作区。默认进入游戏界面，页面选择保存到本机配置，重启后保留。已启用的游戏入口开机启动；鲜牛仍需手动启动，不会在重启时恢复付费计时。

## 游戏模式

用于支持手动 HTTP 代理的设备。外网请求启动星渡自己的 Mihomo 进程，60 秒没有设备外网收发后停止；入口继续等待下一次请求。局域网访问不会唤醒核心或延长外网活动时间。

“接入设置 → 订阅来源”可以选择读取 OpenClash 中已有的订阅。这里读取的是订阅配置，不要求 OpenClash 服务运行，也不会修改它的订阅、DNS、规则或开关。订阅链接不在页面回显。更新订阅是独立操作，不会因为打开页面就下载。

核心可以直接指定已安装的 `/etc/openclash/core/clash_meta`。星渡使用自己的运行目录和只监听回环的后端，关闭 TUN、redir、tproxy；不会调用 OpenClash 启动脚本。设备只需在当前 Wi-Fi 中填写星渡显示的 HTTP 代理地址，保留原有网关与 DNS。

独立订阅的节点策略仍支持香港 → 日本 → 其他地区、首选后回退和固定节点。用途模式与节点策略分别保存。

高级选项“复用已开启的 OpenClash 服务”是另一种运行方式：直接连接现有代理端口。只有这项要求 OpenClash 已运行；其空闲回收不会停止外部服务。

## 加速器模式

在星渡首页点击“加速器模式”，一次点击即可切换并保存。页面会加载鲜牛工作区，已启用的游戏共享继续运行。

账号登录、游戏库、设备、区服、线路、时长和设备偏好复用已安装的鲜牛模块，不复制账号凭据。先选择设备、游戏和线路，再开始加速。设备填写工作区实际显示的代理地址；它与游戏模式的端口可能不同。

免费项目按官方目录的明确标记处理，不恢复或暂停全账号计时；缺少标记时拒绝启动。付费加速停止并获官方确认后再暂停计时。Steam 商店项目不使用商店直连例外。鲜牛运行中也可切回游戏界面；两套服务只由各自的启停按钮控制。

重启后会保留加速器模式，但不会自动启动付费会话或恢复会员计时。游戏模式启用时入口开机自启；加速器页面由 LuCI 提供，无需后台加速进程常驻。

需先安装兼容的鲜牛路由模块。本次配套版本为 `xianniu-router 0.4.4+istore22.9`，包含完成停止、免费计时和工作区互斥接口。

## 命令

```sh
portalproxy mode game
portalproxy mode accelerator
portalproxy check
portalproxy enable
portalproxy status
```

模式切换不调用 OpenClash 服务，不更改主路由、防火墙或系统 DNS。HTTP/HTTPS CONNECT 接入仅承载主动使用它的 TCP；它不会自动接管主机游戏 UDP、语音或 NAT。

实测中 Steam 接口和压缩商店页面可完整传输；未压缩商店大页面仍出现正文不完整。该路径沿用鲜牛实验传输，不将 HTTP 200 状态单独视为整页或实际游戏验收。

首页仅保留用途模式按钮、一个开启/关闭按钮和设备代理地址。核心、订阅、网络参数、节点与运行信息位于折叠的高级设置中。

## 节点偏好

在高级设置中选择“首选后回退”，填写订阅内的完整节点名。例如首选 `HK Hysteria2 Example`，需要先在核心的节点详情确认真实类型为 Hysteria2，节点名称本身不能作为协议依据。该设置优先指定的一个节点，不会自动识别订阅中新出现的所有 Hysteria 节点；首选失效后按香港、日本、其他地区回退。不要把“固定节点”用于需要故障切换的配置。

## PS5 与 Portal

Portal 的代理配置只作用于它遵守手动 HTTP 代理的请求。PS5 游戏服务器连接来自 PS5；在 Portal 上填代理不会自动让 PS5 的游戏 TCP/UDP 经过加速器。本地串流也不应绕行外部线路。

当前 iStoreOS 22 / fw3 配套包支持 HTTP 代理和本机 SOCKS 入口，不启用透明接管。完整设备 TCP/UDP 接管仍要求插件支持的 fw4/nftables 环境，并且设备流量确实经过软路由。HTTP 测试通过不能代替 PS5 游戏联机验证。

游戏共享与鲜牛可以同时运行，分别使用自己的端口和设备名单；切换页面不中断连接，也不会把两个出口串联。完整测试方法及已知问题见[验证记录](router-workspaces-validation-2026-10-26.md)。

会员计时中，页面每秒按上次官方余额倒计时，每 60 秒向官方校准；暂停后不倒计时。每秒显示为估算值，实际余额以官方返回为准。星渡与鲜牛独立页面使用同一个计时组件。

设备卡片可展开“备注”并保存名称。备注与游戏/区服/线路偏好都以规范化 MAC 地址为主键，当前 IP 仅作最后发现地址；换 IP 后不会把备注套到占用旧 IP 的另一台设备。没有可验证 MAC 的设备可以临时接入，但不保存跨 IP 身份。旧版含 MAC 的 IP 偏好会在读取时迁移，首次保存写回新格式。
