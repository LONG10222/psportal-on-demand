# 星渡 StarPass：三种用途与平台对照

日期：2026-10-19。基线为 PR #9 `3e8aab8d7a3ef1dc1997283ea8cb44aeb3546fee`，
叠加本次独立开发分支；未合并 main，也未改写原 macOS/iOS 分支。

## 为什么改名

项目起点是 PS Portal 的局域网代理。现在也能为一般应用提供按需代理，
「星渡 StarPass」表示设备通过受控通道连接所需网络。程序标识、仓库和
原项目署名保持不变，以免破坏更新、配置路径或既有签名身份。

图标采用黑白、简化的双弧通道与星形连接点。它是本项目原创标识，
不使用其他游戏的官方标志，也不暗示合作关系。

## 用途与分流是两层设置

用途模式决定**谁能接入**；规则／全局／直连决定**已接入流量如何出站**。
模式名称不会开启系统级权限，也不会让未支持的协议突然可用。
Android 有独立的规则／全局／直连选择器；本次桌面没有新增同类切换按钮，
provider 仍使用既有规则模式，完整 profile 保留原本的模式与规则。

| 用途 | Windows / macOS / Linux | Android | iOS |
| --- | --- | --- | --- |
| 游戏模式 | 监听指定私网 IP，仅允许设备白名单；排除本机地址 | LAN 共享开启，本机 VPN 关闭 | 目前仅有这一类前台局域网共享 |
| 混合模式 | 相同 LAN 监听，白名单另含本机 LAN 地址；本机应用手动填代理 | LAN 与本机 VPN 同时开启，VPN 必须获系统授权 | 不提供无效开关 |
| Clash 模式 | 仅绑定 127.0.0.1，且只接受 127.0.0.1；局域网设备不可接入 | 仅本机 VPN，不开放 LAN 监听 | 不声称完整 Clash / 本机 VPN 功能 |

### 游戏模式的准确范围

- 面向能够手动设置 HTTP 代理的游戏机／设备，保留最初 Portal 使用场景
- LAN 输入支持 HTTP 与 HTTPS CONNECT 的 TCP，不接管任意游戏 UDP、ICMP 或不使用代理的流量
- 不能据此承诺游戏加速、降低延迟、突破平台限制或所有游戏兼容
- 设备与主机必须处于可互通的可信网络；防火墙授权、Wi-Fi 隔离与热点可达性仍需实际确认

### 混合与 Clash 模式的准确范围

- 桌面不修改系统代理、系统 VPN、DNS 或防火墙；本机应用需支持手动代理并填写实际显示的地址／端口
- 桌面完整 profile 仍由独立 Mihomo 执行；实验性 embedded 路径能力较少。用途选择不会更换引擎、重写订阅规则或伪装成完整 TUN
- Android 本机代理使用现有 VpnService；首次授权、冲突、撤销和通知可见性检查继续有效。VPN 不被保存为下次进程的默认授权意图
- Android 本机 VPN 的 TCP／受支持节点 UDP 以及私有／回环地址限制保持原样；DIRECT 不解除私网限制。LAN 共享仍保留原来的安全直连规则
- Android 后台继续运行选项独立；不能承诺所有厂商省电策略下永久保活

## 对照 macOS 后的实际更新

Windows、macOS 与 Linux 已使用同一套桌面界面和控制代码，因此无需复制一套外观。
本次优先修补实际行为差距：

1. **桌面保存的节点策略**：provider 固定／最快策略在启动与空闲唤醒前恢复。
   后续测速不再把固定节点悄悄切回自动；完整 profile 的逐组恢复行为保持独立
2. **Android 完整 profile 策略组**：可查看真实 select 组成员并明确选取。
   fallback、url-test、load-balance 保留订阅自己的行为；不能选择组外节点。
   成员按需获取，避免把所有组的候选重复塞入每次状态更新
3. **Android 生命周期**：旧弹窗、旧选择结果和停止前排队的命令不能跨会话生效。
   切换仍要求没有活动连接且本机 VPN 已停用；本次选择只在本次会话内存保留
4. **真实状态**：载入不再标成完成测速；Mihomo 的不可用延迟哨兵不当成真实 ms。
   套餐显示服务器快照的获取时间；没有字段不会编造时间或零用量
5. **iOS**：保留已修好的网络变化停止、取消与节点生命周期，只更新可见品牌和
   真实能力说明；没有把受限适配器池冒充为完整 Clash 规则客户端

### 仍然不同的能力

| 项目 | 桌面 external Mihomo | Android full core | iOS 当前实现 |
| --- | --- | --- | --- |
| 自有订阅 / 内联节点 | 支持，受主机安全覆盖限制 | 支持受限内联 profile | 受限适配器池 |
| 完整 profile 分组 / 规则 | 支持受限导入，逐组控制 | 受限内联规则／组，select 手动选取 | 不完整支持 |
| provider 最快策略 | 测量改进＋连续两轮＋保持期 | 原生 Mihomo URL-test 组 | 原生适配器池测速 |
| 本机全应用接管 | 不自动接管，手动代理应用 | 明确授权的 VPN | 无 |
| LAN 共享后台 | 进程运行、主机保持唤醒 | 前台服务，受系统限制 | 必须前台、解锁 |

## 配置与更新行为

桌面 `product_mode` 保存用途；`product_lan_preferences` 独立保留原 LAN 地址／设备名单，
避免本机模式覆盖设备设置。只有明确的 `product_lan_automatic: true` 才允许自动名单跟随
当前子网更新；旧配置和手动名单不会仅凭地址形状被推断为整网段授权。

「一键准备并启动」仅在 `source_provenance` 记录的已接受订阅 URL 和文件路径均匹配时复用，
并在启动前重新检查有大小限制的本地 provider/profile 内容。编辑 URL 后保存不会把旧文件
标成新订阅；来源不明的旧配置有 URL 时会重新导入。文件选择器明确选择的本地文件可独立
覆盖 URL，界面会标注。切用途不清空同来源节点偏好，主动点击「导入订阅」刷新内容；
套餐仍以原获取时间显示，不能冒充新快照。
